# o-naur

See [README.md](README.md) for what this project does and how the pipeline fits together. This file is guidance for AI coding assistants (Claude Code, Copilot) working in this repo.

## Catching up on status

When Sophie asks "where did we leave off", "what's the status", or similar — read `PROJECT_LOG.md` in the repo root and give a short plain-language catch-up: current status, what changed recently, open questions, and suggested next steps. Don't just dump the file back at her.

If `PROJECT_LOG.md` doesn't exist yet, say so and offer to start one rather than inventing history.

## Keeping the log updated

`PROJECT_LOG.md` is gitignored — it's local to this machine only, not shared with the team or committed to project history. After a work session that changes the project meaningfully (new feature, bug fix, decision made, branch/PR opened), append a dated entry: what changed, why, and what's next, in plain language rather than commit-message style.

If Sophie gives you a note in plain language during a session, fold it into that entry in her words rather than paraphrasing it into technical shorthand.
